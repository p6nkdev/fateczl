2. Modelo Entidade-Relacionamento (DER)

Entidade: conjunto de objetos sobre os quais guardamos informações. Forte existe sozinha (CLIENTE, PRODUTO); fraca depende de outra (ITEMPEDIDO precisa de PEDIDO, DEPENDENTE precisa de FUNCIONÁRIO).

AtributoDefiniçãoExemplo
Chave (identificador)Identifica cada ocorrência; vem sublinhadomatrícula
CompostoPode ser dividido em sub-atributosendereço (rua, nº, CEP)
MultivaloradoMais de um valor; marcado com *telefone, e-mail
DerivadoCalculado a partir de outrosidade, total de vendas
ArtificialCriado para identificarcódigo do funcionário

Relacionamento: losango, nomeado por um verbo (a regra de negócio). Cardinalidade, sempre perguntando dos dois lados: "cada FORNECEDOR fornece quantas MARCAS?" e "cada MARCA é fornecida por quantos FORNECEDORES?".

ClasseExemplo da aula
1:1PRESIDENTE governa PAÍS
1:NFORNECEDOR fornece MARCA
N:NALUNO tem aulas com PROFESSOR

Autorrelacionamento: entre ocorrências da mesma entidade (funcionário supervisiona funcionário).

Generalização/especialização (ISA = "é um"): MOTORISTA, SECRETÁRIA e ENGENHEIRO são FUNC; herdam RG, Nome e Data Admissão e têm atributos próprios. Na plataforma: botão + Generalização.

Entidade associativa (agregação): um relacionamento tratado como entidade (losango dentro do retângulo), quando ele precisa se ligar a outra entidade. Nome geralmente é um substantivo. Na plataforma: marque "associativa" na entidade.

Passos do DER: conhecer o negócio → entidades → atributos → relacionamentos → atributos de relacionamento → desenhar → revisar restrições → repetir.

3. Modelo lógico (conversão)
ConceitualLógico
EntidadeTabela
AtributoColuna
IdentificadorChave primária (PK)
RelacionamentoChave estrangeira (FK)
CasoRegra
EntidadeVira tabela; o identificador vira PK
1:1A FK vai em uma das tabelas (a de maior acesso), junto com os atributos do relacionamento
1:NA FK vai na tabela do lado N, apontando para a PK do lado 1; atributos do relacionamento também vão no lado N
N:NNova tabela com PK composta pelas duas PKs (que também são FKs) e os atributos do relacionamento; vira dois 1:N
MultivaloradoNova tabela com a PK da entidade + o valor (como cliente_telefone)

Generalização não aparece nas regras da aula; na plataforma a resposta usa uma tabela por subclasse (com a PK da superclasse) e também aceita uma tabela única.

4. Normalização (1FN, 2FN, 3FN)

Objetivo: tirar redundância e evitar anomalias de inserção, atualização e exclusão.

FormaPerguntaO que fazer
1FNRepete? (grupo repetitivo, multivalorado, composto)Separar o "dono" que se repete; o resto leva a chave dele e fica com chave composta. Derivado sai.
2FNDepende de metade da chave composta?Levar para a tabela daquela parte da chave

5. SQL – DDL (criar a estrutura)
CREATE TABLE ItemNota (
  NumeroNota numeric(10),
  CodProduto int,
  Quant int NOT NULL CHECK (Quant > 0),
  PRIMARY KEY (NumeroNota, CodProduto),
  FOREIGN KEY (NumeroNota) REFERENCES NotaFiscal(NumeroNota),
  FOREIGN KEY (CodProduto) REFERENCES Produto(CodProduto)
);
ALTER TABLE TabAluno ADD notaexame numeric(10,2);
ALTER TABLE TabAluno MODIFY nome varchar(100);      -- muda tipo/tamanho
ALTER TABLE TabAluno CHANGE nome nomealuno varchar(35); -- renomeia
DROP TABLE TabAluno;

Características: AUTO_INCREMENT (só na PK), NOT NULL, PRIMARY KEY, UNIQUE, DEFAULT, CHECK. DDL = CREATE/ALTER/DROP; DML = INSERT/SELECT/UPDATE/DELETE; DCL = GRANT/REVOKE.

6. SQL – DML e consultas
INSERT INTO tabalunos (nome, curso) VALUES ("Maria", "ADS");
UPDATE tabalunos SET nota2 = nota2 + 0.5 WHERE nota1 < 8;
DELETE FROM tabalunos WHERE matricula = 20;
SELECT nome, (nota1+nota2)/2 AS Media FROM tabalunos
 WHERE curso IN ("ADS","COM") AND nome LIKE "M%"
 ORDER BY nome DESC;
SELECT curso, COUNT(*) FROM tabalunos GROUP BY curso HAVING COUNT(*) > 3;

WHERE filtra linhas antes de agrupar; HAVING filtra grupos. COUNT(*) conta linhas; COUNT(coluna) ignora nulos. BETWEEN inclui os extremos. Use IS NULL, nunca = NULL.

7. JOINs
SELECT NomeFunc, NomeDepto FROM Funcionario INNER JOIN Depto ON DeptoFunc = NumDepto; -- só quem combina
SELECT NomeFunc, NomeDepto FROM Funcionario LEFT JOIN Depto ON DeptoFunc = NumDepto;  -- todos da 1ª
SELECT NomeFunc, NomeDepto FROM Funcionario RIGHT JOIN Depto ON DeptoFunc = NumDepto; -- todos da 2ª
SELECT f1.NomeFunc, f2.NomeFunc AS Supervisor            -- autorrelacionamento
FROM Funcionario f1 INNER JOIN Funcionario f2 ON f1.supervisor = f2.IdFunc;
8. Subconsultas
SELECT * FROM EMP WHERE esal = (SELECT MAX(esal) FROM EMP);           -- valor único
SELECT empno, enome FROM EMP e WHERE EXISTS (SELECT * FROM FONES_EMP f WHERE e.empno = f.empno);
DELETE FROM DEPTO WHERE deptno NOT IN (SELECT DISTINCT deptno FROM EMP);
UPDATE EMP SET esal = esal*1.1 WHERE deptno = (SELECT deptno FROM DEPTO WHERE dnome = 'compras');
INSERT INTO GERENTE SELECT empno, enome, esal FROM EMP WHERE efuncao = 'gerente';

IN = "= ANY"; NOT IN = "<> ALL"; ANY = algum (OU); ALL = todos (E). Com "=", a subconsulta precisa devolver uma linha só. MySQL não tem EXCEPT/INTERSECT: use NOT IN e IN.
